# CPU attention · 完整调用与归约顺序

## x86 默认档 unscaled 的两种实现

用同一份 B=2、Q 头数 32、KV 头数 8、序列长 2048、头宽 128 的 BF16 输入检查生成程序。两者都使用 oneDNN BF16 BRGEMM。下列周期是改前一次完整调用累计的工作线程周期，不能作为墙钟时间相加。

| 阶段 | Mojo | Weft |
|---|---|---|
| 并行、供数 | OpenMP 动态调度 512 个任务，每任务 256 行 Q。每批 16 行打包 Q，一次预打包 V | 同一 CPU 决定给出 256 行，出口原先再截到 64 行，共 2048 个任务。K 和 V 分别预打包 |
| QK、最大值 | 每 16 行做一次 2048×16×128 的 QK，8192 次。只对因果前缀求峰值 | 32 行 Q × 128 个 K，按因果上界截短，每个完整调用做 34,816 次 32×128×128 的 QK |
| 指数、行和、收窄 | 沿 16 行用向量 exp，在同一循环累加 FP32 行和并写 BF16 权重，最后转置有效前缀 | 逐 K 块更新峰值，在 32×128 的分数上做掩码、exp、行和与 BF16 收窄，同时按新峰值重缩放已有输出 |
| PV、临时区 | 每批一次 16×128×前缀长度的 PV，8192 次。FP32 分数和 BF16 转置缓冲在任务入口分配，跨批复用 | 34,816 次 32×128×128 的 PV。库调用之间产生固定大小的权重与有效位面板，输出反复重缩放 |

Mojo 的 QK、峰值、指数/行和/收窄、权重转置、PV 及其边界分别占 184、60、112、46、313 百万工作线程周期。Weft 的 QK 与 PV 分别占 140、101 百万周期，库外占 569 百万。任务内指令采样有 7842 个落点，2984 个落在指数，969 个落在掩码及峰值，377 个落在行和，476 个落在收窄，618 个落在重缩放。

**指数口径。** 原始 Mojo 产物调用 `std.math.exp`。本轮共用的 CPU 决定只给同时供 FP32 行和、BF16 点积权重的自然指数登记 AVX‑512 参考默认。ATen 的 CPU SDPA 在这个向量分支调用 `fexp_u20`，普通向量 FP32 分支调用 `exp_u20`，标量尾部调用 `std::exp`。Inductor 的普通 `CppVecOverrides.exp` 调用向量 `.exp()`，在本机对应 SLEEF 的 `Sleef_expf16_u10`。作者的 `approximate=False`、显式 IEEE 和严格数值选项保留源指数。在线重缩放仍计算其独立的 FP32 指数。[ATen SDPA](https://github.com/pytorch/pytorch/blob/449b1768410104d3ed79d3bcfe4ba1d65c7f22c0/aten/src/ATen/native/cpu/FlashAttentionKernel.cpp#L83-L115) · [AVX‑512 实现](https://github.com/pytorch/pytorch/blob/449b1768410104d3ed79d3bcfe4ba1d65c7f22c0/aten/src/ATen/cpu/vec/vec512/vec512_float.h#L307-L368) · [Inductor](https://github.com/pytorch/pytorch/blob/449b1768410104d3ed79d3bcfe4ba1d65c7f22c0/torch/_inductor/codegen/cpp.py#L1254-L1258)

从两个出口的产物提取权重指数，4096 个含下溢边界的输入及 65,528 个随机有限输入均与本机 ATen 逐位相等。正、负无穷及精确溢出阈值另测。对 NaN，两出口保留 NaN；ATen 的 AVX‑512 向量函数直接调用时返回负零。 对区间 [−80, 0] 均匀采样 65,536 个 FP32 输入，与以 FP64 计算的 exp 比较，`fexp_u20` 的最大实测相对误差为 0.0111%，与舍入到 FP32 的参照最多相差 973 ULP。函数名没有给这个 BF16 权重分支提供 20 ULP 的保证。

Weft 现采用共享的 256 行任务粒度，以无符号除余解码非负任务坐标。triton-weft 在向量寄存器中归约有效位，只有进入标量回退时才写出逐 lane 掩码。Xeon 绑核 0–7，三轮交错，每侧每轮 11 个样本，按倍率居中的整对展示。Weft 改前复测为 52.72 / ATen 31.93 ms，改后为 **38.47 / 31.45 ms**，倍率 1.65 → 1.22。改后三轮依次为 38.47/31.45、30.21/26.94、33.67/27.16 ms。Mojo 改后为 38.15/26.20、27.76/25.88、36.82/25.39 ms，Bench 按离散度仍判平。Weft 剩余的结构差别在于固定 K 块跨库调用传递分数、权重和重缩放输出。把更宽的 K 块直接物化为整面板已测得回退，后续候选需要能让 PV 消费实际前缀长度并复用暂存空间。


两项使用第七组的固定输入，BF16，2 个 batch、32 个 Q 头、8 个 K/V 头、序列长 2048、头宽 128。下表均计入输入相关的面板准备和输出写回。

## 默认 BF16 点积与 x86 面板复用

Intent `dcbe2e0`、triton-weft `a9cd181f8`。Xeon 绑核 0–7，完整调用与同轮 ATen 交错三轮，每轮预热 3 次、测 11 次。两项的作者均允许块内在线归一化。下表的旧默认和新默认使用相同的下游优化器，仅产品选择不同。

| Xeon 完整调用，ms | unscaled | ALiBi |
|---|---:|---:|
| 旧默认，FP32 乘积 | 140.40 | 190.83 |
| 新默认，模型选择 32 Q × 128 K | **50.93** | **42.88** |
| 新默认，强制 256 Q × 512 K | 67.34 | 78.22 |
| 同轮 ATen CPU FlashAttention | 27.41 | 50.58 |

模型按行和与 PV 共用的一份 FP32 权重估算缓存流量，在线候选保留块内依赖。triton-weft 将同域、单消费者且可安全移动的逐元素链按行向量化，包含 exp 和重缩放。MLIR buffer-loop-hoisting 将可复用缓冲移出内层循环。大块 unscaled 每次调用中约 512 KiB 的分配从 13,824 次降到 2,560 次。与旧下游的大块相比，两项在 BRGEMM 外的工作线程周期从 2,623/2,958 百万降到 866/1,122 百万。256×512 仍慢于模型选中的块。

次正规输入反例中，Q 含 2⁻¹²⁷，一半键的有效分量为 2¹²⁷、值为 1。末行 Weft 默认和 ATen 均为 0.5。显式 IEEE 和显式 FP32 乘积均为 0.73046875。第二个反例的非零 V 为最小正规 BF16，第二个键的有效分量是 −0.6953125。其注意力权重与 V 相乘后落入次正规范围。默认和 ATen 均为 0，显式两档返回 BF16 位型 `0x002b`。SG2044 的默认和显式 IEEE 分别在两组上均得 `0x3f3b` 和 `0x002b`。SG2044 固定核 48，预热后交错三轮，默认 Weft 两项分别为 45.44、45.13 秒，同轮 NumPy/OpenBLAS 为 41.35、47.82 秒。两台 CPU 各通过完整 71 项。[各出口的窄精度点积合同](../design/kir.md#窄精度点积的目标语义)

## 前一轮的块内在线归一化

2026-11-27，Intent `97ef936`、triton-weft `69200952d`。Weft 将私有循环累加器的逐行缩放和 PV 的 BRGEMM 串接到同一缓冲区。缩放须在 contraction 前，携带的数组、缩放结果和加法各有唯一使用者，原始累加只有在乘加都获得相应数值许可时才融合。循环初值如有别处引用，在循环外复制。未授权加法、复用初值及多次迭代的结果均在下游回归中核对。

块内权重、行和与旧累加器的重缩放共用 0.6 的归约链变换。CPU 模型按 BRGEMM 形状、行与列的复用、私有缓冲、两级缓存和下游向量容量计价。Xeon 的 48 KiB L1D 和 2 MiB L2 上，两项都选中 32 行 Q × 128 个 K。每个面板调用两次 BRGEMM；任务 IR 中跨两趟的 `local_alloc` 从 1 变为 0。Mojo 共用 CPU 决定，仅枚举其出口能实现的候选。

核 0–7，3 次预热、11 次采样，三轮轮换顺序。下表每格是三轮完整调用中位数的中位数。

| Xeon，ms | unscaled | ALiBi |
|---|---:|---:|
| Weft 两趟、PV 原位累加，preserve-sign | 47.53 | 45.95 |
| Weft 块内在线，preserve-sign | **42.62** | **44.65** |
| 同轮 ATen CPU FlashAttention | 24.76 | 48.74 |
| Weft，0.6 默认 IEEE 次正规数 | 174.43 | 235.09 |

在单独的插桩运行中，unscaled 的非 BRGEMM 工作线程周期从 722 降至 636 百万，QK 和 PV 合计从 291 变为 323 百万。ALiBi 的非 BRGEMM 周期从 559 变为 585 百万，两次 BRGEMM 合计从 354 降至 182 百万。插桩覆盖任务入口、两个库调用和任务出口；非 BRGEMM 周期包括掩码、权重、行和、重缩放和其余数据移动。

两个程序都显式声明 relaxed normalization。0.6 解析到 source 时保留两趟路径；在同样的 preserve-sign 下，两项和改前逐位相同。严格 IEEE 在 63、128 两种长度和正、零、负 scale 下均逐位一致。另用 128、255、256、2048 四种长度和三种 scale 核对实际候选，24 组通过。255-token 的输入自动选回两趟。32×64、64×32、64×64、256×512 等候选也用完整调用测量，256×512 即使减少库调用次数，实测仍达 165.58 / 191.53 ms。

| SG2044，核 48，单线程，秒 | unscaled | ALiBi |
|---|---:|---:|
| RVV 二维 FP32 contraction，4×4 | 48.10 | 47.11 |
| 栈容量允许时配对 K 面板，4×8 | **46.71** | **47.07** |
| 同轮 OpenBLAS | 47.54 | 47.99 |

SG2044 每条路径预热一次，随后三轮交错。FP32 QK 保留乘积舍入，PV 前权重先舍入到 BF16。模型把 FP32 乘积、有效位、保留的分数、输入和输出共同计入私有栈，容量足够才增宽。ALiBi 两个宽度持平。

## 前一轮 Xeon Platinum 8470Q

固定 0–7 核。每轮交错运行各候选和同机 ATen，每项预热 3 次、测 11 次，表内为三轮中位数，单位 ms。ATen 两项都调用 CPU FlashAttention。因果标志允许 unscaled 缩短 K 的扫描范围，ALiBi 的稠密偏置需要扫描全部 K。

| 实现与许可 | unscaled | ALiBi |
|---|---:|---:|
| Weft，0.6 默认 IEEE | 161.43 | 230.08 |
| Weft，`preserve-sign`，PV 后独立加回 | 61.35 | 62.74 |
| Weft，`preserve-sign`，PV 原位累加 | **50.49** | **47.44** |
| 在线候选，64 Q × 64 K | 53.81 | 56.41 |
| 在线候选，256 Q × 512 K | 158.98 | 201.51 |
| 同轮 ATen | 25.91 | 50.70 |

原位累加来自 triton-weft 的 x86 contraction 降级。加法和源乘法的合同共同许可融合与重排时，单消费者归约可用 oneDNN 的 `set_add_C`。循环携带的缓冲区须为该迭代独占、回边须返回该结果。保留其他引用的初值在循环外复制一次。默认 IEEE 模式下，两个作者程序的宿主代码和任务 IR 在改动前后逐字一致。显式 strict 路径在两个序列长度与正、零、负 scale 上逐位复核。

在线候选复用了 0.6 归约链的重缩放，将 QK、FP32 行最大值与行和、BF16 权重、PV 串成一次面板扫描。两种尺寸都消除了跨遍历的分数写回，生成的两次 BRGEMM 分别使用覆写和累加。用任务入口、出口与两个库调用边界计工作线程周期。unscaled 在原位两趟、在线 64×64 和在线 256×512 下，两次 BRGEMM 以外分别耗费 642、708 和 2968 百万周期，ALiBi 为 605、644 和 3398 百万。大面板减少了 PV 库调用内的周期，但每块的行重缩放、权重生成及相关数据搬运合计更贵。两项完整调用均回退，已撤回在线候选和相应代价模型调整。

## 前一轮 SG2044

核 48，单线程。两次 QK 扫描在原实现的任务内软件采样中合计占 unscaled 的 66.1%、ALiBi 的 63.6%，包含乘积、横向归约与第一遍行峰值。原实现逐 Q 行读 K。新候选按共享 K/V 的独立 Q 行分块，行数受向量长度和寄存器数量限制，候选同时检查私有面板的存储开销。QK 可重排归约时仍遵守乘积舍入，默认生成单独的 FP32 乘法及加法归约。获得许可的 PV 可用 RVV FMA。放开两处 FMA 的试验曾得 31.28/33.31 秒，缺少 QK 的融合许可，该实现已排除。

同机 NumPy/OpenBLAS 对照在计时内把 BF16 输入提升至 FP32，并先将未归一化权重舍入至 BF16，再做 PV 和归一化。时间单位为秒。原实现列取本轮预热后的首个完整调用。二维候选与 OpenBLAS 各预热一次，取后三次完整调用中位数。

| 实现 | unscaled | ALiBi |
|---|---:|---:|
| 原有逐行 Weft | 104.15 | 106.35 |
| Weft 二维 FP32 分块，SG2044 本机构建，0.6 默认 | 52.12 | 48.05 |
| NumPy/OpenBLAS | 43.69 | 45.39 |

SG2044 上每个面板用 4 个 Q 行和 4 个 K。显式物化未融合的 FP32 乘积时，4×16 需要 89,014 字节，超出 65,536 字节的私有存储上限。4×4 的本机构建产物使用 50,685 字节。此前用 SG2044 的设备事实在 x86 导出、在 SG2044 编译执行的同一方案分别为 44.36、44.79 秒，该轮 OpenBLAS 为 40.02、40.40 秒。源 IR 中的 QK 归约只允许重排，周边的近似指数不授予 QK 乘加融合许可。对照反例使用两个 BF16 输入产生溢出的 FP32 乘积，检查两个程序在默认和 strict 下的 NaN 行及其前面的有限输出。

验收使用同一提交的 x86 和 SG2044 本机构建。两个设备各通过 53 个发布用例与 18 个第七组用例，SG2044 的设备输出经独立 Bench oracle 核对。五出口 readiness 完整，`custom=0`、`parity_todo=[]`。
