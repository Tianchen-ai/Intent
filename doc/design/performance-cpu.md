# CPU 任务与遍历的性能决定

| 适用原则 | partition 家族候选 | 分项 | 机器参数 | 验证 |
|---|---|---|---|---|
| 每个输出只属于一个任务。交换独立坐标能让内层沿目的地址连续前进 | 按源行、按目的行、二维 tile | 每个流的有效字节、内层 stride、触及缓存行数，读与写分计 | cache line 字节数，连续及跨步读写带宽 | 转置、普通逐元素 |
| 二维块的工作集能留在缓存时，相邻任务可复用读入的行 | 矩形 tile 与完整行 | 活跃输入和输出块的工作集，按行跨越的边界、重新加载量 | 数据缓存容量、带宽、写分配成本 | 原始与非整除转置 |
| 任务太短会让派发与 join 主导，过长会造成最后一波不均衡 | 不同 grain，尾块保留实际 extent | 批次数、最后一波的活跃 workers、派发和汇合时间 | affinity 下可用 workers、固定启动和同步延迟 | 小矩阵和宽矩阵 |
| 连续向量与间接 lane 的成本不同；不足一向量的尾段仍要计入 | 整行、向量面板 | 向量运算数、有效 lane 比例，结合内层 stride | 实际向量宽度与出口原生实现的吞吐 | 行归约、转置尾部 |

任务节点决定 ownership 和遍历。出口估计原生向量与供数成本，并兑现同一个任务合同。库调用的线程数遵循本机执行集合。


## 当前采用与模型误差

双射矩阵复制的 `permutation` 家族登记源行、目的行和二维 tile。默认配置仅登记策略和 realizer；三个候选由当前 CPU 模型按本次 shape、物理 stride 和执行集合排序。可在派生编译器中固定其中一项以比较生成结果。

tile 内层沿源行前进，块的边界缩短连续执行的跨度。对单个执行者，模型按内层跨度、物理步长和缓存组映射，从合成面板读写样本中插值单位字节时间。多个并发输出所有者使用相邻条带共享缓存行的合成样本。gather 和 scatter 的每个样本都包含一读一写。CPU 节点共用向量发射估算，向量宽度和实测吞吐来自目标。

Mojo 的矩形直接复制可兑现为完整的一维 copy sweep。其 verifier 核对两个二维视图、匹配的读写值及覆盖范围。一般逐元素计算继续使用向量 sweep 和尾段。Weft 和 Mojo 的 host 将同一执行者的连续 grain 合为一个原生区间，遇到投影视图的行边界时重新绑定地址。

## 元组状态与输出归属

通道归约把通道区间分给任务。并行任务可以独立写输出和 running state。
元组归约策略读取 Welford 操作与目标行参数，计价时每个非空归约域有
`members - 1` 次摘要合并，每次计八次浮点运算等价工作。当前吞吐项采用已校准
的向量吞吐；有序状态带来的指令依赖延迟尚未单独标定。读统计与写统计都是
owner 投影，不能与对整块样本的读写合并计数。验证程序为训练 BatchNorm。

## 前缀与间接读取

扫描将整行交给同一任务，分块之间显式传递末项；计算代价包含每行的依赖加法。Mojo 在完整 SIMD 块与尾段之间延续同一 carry，Weft 在 native task 的 scf.for 中携带它。行查表索引沿 owner 轴，数据表共享，提交批次不能切走表头。Mojo 对独立连续行选择整行复制，非连续 view 沿实际 stride 读取。
