# DSA 的显式存储程序与 BANG C 出口

**V2-5 设计，待裁决。** 首个消费者是 MLU370 上的 softmax 和 weighted RMSNorm。本轮仅查询设备与工具链，不据此声称 V2 已在 MLU 上编译或执行。

```text
block@realized → dsa@formed → dsa@supplied → bangc@bound → @legal → @callable → .mlu
                       └── supply 家族 ──┘                             ↓
        同一份参数化程序，沿途保留 row ID                   CNCC、本机库、CNRT 队列
```

## 1. DSA 接收的程序

从 realized 取得实例覆盖和逻辑输出责任、具名行组与 guard、片段坐标、有效域、归约代数、循环 carry 和 effects。此处所有 Block 结构决定已兑现；无需借用某个 GPU 语言出口的规范化 pass。DSA 保留作者的 kernel 数、实例覆盖和归约语义。在这些约束内，决定由谁准备数据，在哪个可见范围持有数据，哪些搬运能与计算重叠。

| 表示 | 生产者 → 消费者 | verifier 检查的性质 |
|---|---|---|
| participant、execution group、ownership | 父程序的实例映射 + 出口能力 → DSA 调度 | 计算、搬运、协作等角色各有参与域；每个活跃输出恰好有一个写者或有显式合并语义。分组可复用同一物理参与者处理多个逻辑实例；组宽、专用搬运者、可用引擎来自能力服务。 |
| storage resource、区域与槽 | 出口声明不透明资源 ID、作用域、读写与可达引擎；DSA 选择资源并建模 → 出口地址绑定 | 区分设备可见、组可见、参与者私有。槽有类型、对齐、行参数化的 extent、owner、初始化事件、最后一次使用事件。公共代码只查询库存和关系；它能表达不同数量、容量和可见范围的资源。 |
| transfer、compute、completion、wait | 已选供数结构 → 显式 DSA 操作与 SSA 完成值 → 目标原语 | 搬运声明源/目的、stride、有效区间、执行角色和读写 effects；计算声明输入就绪及结果完成。只有完成点支配实际使用，等待作用域覆盖生产者和消费者才合法。同一组共享数据还须有目标支持的可见性保证。尾块同样受 bounds 和 effects 约束。 |
| lifetime 与 reuse | 完成依赖和别名分析 → 分配/复用 | 最后读或异步写回完成前不得覆盖地址。以依赖的偏序计算可能同时存活的槽，计入并发副本、对齐、微核 scratch 和长期状态。同地址复用要求结束先于下一次初始化；共享读者全部完成后才能释放。 |

### 决策、边界与失败归属

| 节点 / 家族 | 决定、事实与输出 |
|---|---|
| 必需 lowering → `dsa@formed` | 保留真实计算区域，建立抽象参与者和供数关系。查询目标搬运粒度、同步作用域、计算实现的输入表示及 scratch 需求。不能用空 capability 或未知容量支撑某一行合法。 |
| `supply`，formed 决定、supplied 兑现 | 一个区域只提交一次联合决定：供数拓扑（直供/组共享、单/双缓冲、深度、等待位置）加上与之相容的完整行。策略按计算模式登记，读取同一份 effects、复用和寿命分析。保留父行 ID 与本地资源承诺的对应，不交叉枚举尺寸与流水深度。对每一行检查预算、尾块、协作范围、等待是否可达，失败记录 row ID、资源或事件、需求与可用量。此阶段剔除无法兑现的行，只在剩余行中调优。 |
| `dsa@supplied` | 将联合决定展开成参与者区间、分配、槽选择、搬运、计算、完成、等待与释放的当前 IR。所有行使用相同控制/供数拓扑，行值只改变尺寸与容量。逐行复核写后读、读后写、组共享可见性和重叠峰值；禁止存在待兑现决定或靠 serializer 添加 wait 才成立的 IR。 |

**两行例子。** 沿用 [Block 的算例](block.md)：M=3、N=1100、f32，深度 2，输入两槽、输出一槽，槽大小为 `align_up(4RW,128)`。演示预算为 16 KiB。A 行 (R=1,W=512) 占 6 KiB；B 行 (2,512) 占 12 KiB，第二行组只写一行。它们对第 k 块都等待本块搬入完成，在覆盖输入槽前等待第 k−2 块计算完成，覆盖输出槽前等待前一块写回完成；末尾排空。两行尾块都只有 76 列。C 行 (2,1024) 要求 24 KiB，在 formed 剔除，并注明少 8 KiB。不能单为 C 改用深度 1。归约程序使用同一检查方法，但需要另外计入累加器、增益及微核临时量。

## 2. MLU370 能力与经验行

本轮对 device 0 调用 CNRT 只读查询，得到 4 个 cluster、每簇 4 个计算核、每核 NRAM 786432 B、每核 WRAM 1048576 B、每簇 SRAM 4194304 B；本机 CNCC 为 4.7.2。安装头文件明确 `cnrtAttrSramSizePerMcore` 的单位是**每簇字节数**。容量表属于 `exits/bangc/capabilities`。公共 DSA 看到的是带作用域的资源描述，不能把每簇容量乘核数后给单个分组。

物理容量、SDK/ABI 保留量、微核占用、产品允许的工作集预算分别记录来源。若 CNRT 报告的是已可用上限，应显式标明，避免二次扣减。每资源实际峰值须 ≤ min(已核实可用量，行预算)，共享资源按同驻者聚合。工具链保留量未知时，使用有该工具链依据的保守上限或拒绝相应实现；不得把未查询的保留量填成零。

首轮建议两套**分别派生**的配置，数值是待验证的起点。BANG C 在父节点通过既有 RowCapacity 提供公共 R、W 及行 ID；下表以流式 W=512 类说明。小宽度可声明 1、2、…、512 的有限宽度类，由 Block 产生实际 guard。

| 配置 | 同组两行 | 出口承诺 |
|---|---|---|
| 直接供数，默认 | (1,512)、(2,512) | 计算参与者从设备内存直供私有槽，单缓冲；建议各用至多 16 个并行计算任务，超额逻辑实例由核上循环覆盖。两行预算初值各 128 KiB 私有工作集。 |
| 重叠供数，派生 | (1,512)、(2,512) | 两个输入槽、一个输出槽；仅当本地 SDK 的异步搬运、完成和可见性支持所选拓扑，才准入。不要让普通行归约无端占用共享 SRAM。 |

这两项行程序使用向量单元；不分配矩阵权重空间。矩阵实现另外登记完整行，包含 M/N/K 块、输入 packing、权重空间、对齐、累加类型、尾块与所需执行组。受管 hint 可表达 Block/Union 等目标运行模式；参与者的物理编号和厂商枚举只存在于 BANG C 目标组件。

## 3. 出口边界、微核与原生接口

| 边界 | 生产者 → 产物及检查 |
|---|---|
| `bangc@bound` | 在声明的引擎与存储可达性内，将 DSA 资源绑定到 GDRAM、NRAM、WRAM 或 SRAM，将角色绑定到实际组、计算核及适用的搬运支持。选择能消费当前 typed region 的微核，按行验证 SDK 对齐、尾块、暂存与原语签名；固定槽 offset、空间和 ABI。物理要求无法满足时剔除该行并给原因，不重新选择 Block 拓扑。 |
| `bangc@legal` | 兑现地址和字节长度、连续/跨距搬运、向量/矩阵原语、异步提交与等价等待。区分本地引擎完成和组级可见性；barrier 处所有必需参与者到达，部分尾块用谓词限制搬运，不能让部分参与者跳过公共 barrier。空间不同的同偏移不能互为指针。 |
| `bangc@callable` | 已闭合 `.mlu` 入口、host launch wrapper、队列/设备参数、native function type、维度标量与指针槽、行常量和 workspace 大小/对齐。serializer 只输出已经形成的循环、指令与同步。CNCC 面向已探测的 MLU370 兼容架构原生编译、链接可加载模块；保留每行的工具链失败信息。 |

**微核合同。** collective 微核接收活跃片段、dtype、归约轴/identity、累加器，返回局部摘要及完成值；由外层维护跨块累加、次序和写回。矩阵微核接收 typed contraction 的分块与前次累加值，声明两侧输入布局、packing、WRAM 需求和 scratch，返回更新后的累加器。可共享的 packing 在生产者作用域做一次，直至所有消费者完成。供数微核按有效 extent 和地址空间发起复制/等待。选择依据是类型、访问和资源合同，不按程序名派发。原语对 NaN、次正规数或混合精度不符合作者许可时，使用合同等价的微核或报告能力缺失。

**地址和 workspace。** 设备外部参数携带真实 view 的数据起点、形状、元素 stride 和 owner；host wrapper 与设备代码约定一次 offset/byte 换算。局部槽进入片上分配。真正需要跨参与者/阶段共享的设备内存以显式 workspace ABI 发布，声明大小公式、对齐、初始化与释放完成点，且不得与可写实参发生未声明的别名。两项行程序优先将跨块标量摘要保存在私有状态；只有指明存活区间和容量后才允许额外 workspace。

## 4. 两个程序沿边界走读

| 边界 | Stable softmax | Weighted RMSNorm |
|---|---|---|
| block@realized | 活跃行在 f32 中依序求最大值、exp 的和、归一化；保留驻留或重读循环。 | 同行平方和，读真实 inv 与 eps，按列读取 gain，最后一次写回。 |
| dsa@formed | 为读入、标量行摘要、exp 计算和输出槽选择同一种供数图。若选驻留，按行计算整行片段加临时量能否同时存活；流式按既定遍历重读。 | X 的私有槽、行内平方和与缩放因子有明确 owner；gain 按列投影。只有跨消费者复用确实存在且预算充足才选择组共享准备。 |
| dsa@supplied | 每个有效块搬入后才能计算；每遍结束，前一遍摘要完成后下一遍才能读取。物理尾部对 max 和 sum 分别中和，最后一次写回完成再释放槽。 | 搬运 X → 求平方和 → 完成 rsqrt → X 和 gain 两条输入边就绪 → 相乘、窄化及写回。零工作量不发搬运，尾部只写活跃地址。 |
| bangc | 绑定私有空间与 collective 微核，保留 NaN 传播和 f16→f32→f16 语义，产生单 kernel。 | 选择 f32 collective 与向量乘加/缩放的等价实现，gain 使用其自身 stride。不得暗中重结合或以近似 rsqrt 改变许可。 |

## 5. runtime 与扩展成本

`runtime/kir` 提供签名、容器设备与所有权。`runtime/block` 对 guard 和逻辑 grid 求值。`runtime/bangc` 在目标设备上下文使用调用方当前 CNRT queue，按出口已经发布的映射将逻辑实例交给 native launch。prepare 绑定输出与本次 workspace；compile 编译所有适用行，不调优/执行。首次 launch 只在同一供数拓扑的合法行组内试跑，以同队列的开始/结束 notifier 包围完整 kernel，等待结束后读取设备耗时。试跑使用独立可写 storage、保持 view 之间的 alias 与偏移；每次重放前恢复 InOut 初值和必要初始化。最后只把 winner 对真实实参执行一次。模块、临时 workspace 与输入存活到队列完成；热 launch 不插入全设备同步。loader 检查 ABI、CNRT/CNCC 与设备匹配，winner 的身份含实际工作量、stride 类和行组，缓存不得保存上次的实参地址。

**加法成本。** 新增 storage 级的 dsa 节点、bangc 出口与 runtime/bangc，产品登记和默认配置随之更新。两项行程序预计对现有 KIR、CPU、Block、Triton、cuTile 及其 runtime 的功能修改均为零。DSA 从 realized 接出，因此不能假设 normalized 已显式化行广播；应按已存在的片段语义消费，读一维 gain 可引用 Block 的公共轴投影查询。若实际需要新的共享访问语义，在 Block 明确提出，不在出口按 rank 重新猜测。当前两个行程序的片段值和 mask 已经足够；矩阵和任意索引属于后续语言/Block 覆盖。

V1 的 BANG C BlockLowering 在配置循环中 clone module 并逐次构造 Block storage；较早 DSA 公共 verifier 还以二维 NRAM tile、memory core 等形式定义公共合法性。当前 V1 checkout 的一部分物理检查已经归入 BANG C 私有目录。V2 在选定出口时只运行一次 KIR→Block→DSA；每行资源校验遍历同一参数化区域，原生行特化从已绑定出口程序开始。由产品树、阶段 verifier、能力服务共同约束这一点。

## 6. 请裁决的实现选择

1. 首轮默认使用单缓冲直供，还是两程序均以共享双缓冲为默认？建议直供；双缓冲作为单独派生配置，比较时同时计入额外槽、尾声等待和同步。
2. 地址 ABI 可保留动态 extent/stride，仅特化必须静态的微核参数；也可对子形状全特化。建议前者，将必要的对齐/形状 guard 随产物发布。
3. 多行可共享一个带完整参数行的原生模块，也可为确需编译期常量的微核分别生成原生入口。建议共享出口 IR，允许后一种原生特化，按行或共享构建如实计冷启动。
